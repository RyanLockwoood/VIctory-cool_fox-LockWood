- **Detiling on the card, step 3: wired in behind `VICTORY_GPU_DETILE=1` (off by default).** Backup tag `backup-before-gpu-detile-wiring-20261128`.
  - **Which textures:** at staging creation, a texture gets `Staging::gpu` (one `DetilePlan` per part) when the switch is on, it is not levels on demand, and every staged part has 4-, 8- or 16-byte elements in an addressable mode with addresses within 32 bits. Movie planes (R8) never qualify. Every other texture is unchanged.
  - **Refresh:** for such a texture `Staging::detile` copies the tiled bytes as they are into staging (`read` bytes, `VICTORY_DETILE_TIMING` counts it). Staging is sized `max(rows, read)`. The dirty/uploaded flow is untouched.
  - **Recording:** in `record_upload` (only when the source is the staging buffer itself), `HostList::detile_work` records into the list's side list: copy staging into a card chunk, barrier, one dispatch per part and depth slice into a second chunk laid out as the footprints, barrier UAV to copy source. The list's `CopyTextureRegion`s then read that chunk from offset 0. The side list binds only its own compute pipeline; the list's own state is never touched, so no draw-state cache needs clearing. If recording fails, the upload is skipped with a once-log (staging is not in rows, so the processor cannot copy it).
  - **Submission:** in `Host::submit`, after the last refreshes and `make_waiting`, the runs' closed side lists go in a queue call of their own ahead of the submission's lists (same queue). `HostList::close` closes the side list. `Deferred::detile` holds the side list and chunks until the list's reset (all its submissions have run): side lists go back to a pool (64 kept), and card chunks (powers of two from 64 KiB) to a pool of up to 256 MiB kept. Tables are one small upload buffer per mode and element size, kept.

- **Descriptor cache design (read-only).** `make_twinned` makes, per view kind: `Constant` (CBV on the shadow buffer found by address, `Kept` = that buffer), `Shader` (SRV of the texture's host copy via `resource::host_copy`, desc fitted to it; buffer views via `buffer_srv`), `Unordered` (UAV, of a depth texture's colour twin where needed), `Sampler`/`ConsoleSampler` (no resource), `Placed` (via `make`). When nothing can be made, `null_for` makes a null view whose content depends only on the view's kind and the title's dimension/format, with no resource. Descriptors are already made into per-thread staging slots and copied into the heap (`staged`, `copy_to`). Plan in two stages, each behind its own switch: (1) **null views and samplers**: cache one made descriptor per distinct null description or sampler words and copy it; no resource involved, so nothing can go stale; add per-kind counters (null / constant / texture / unordered / sampler) of made and repeated so the remaining share is known. (2) **resource views**: key by view key plus the host resource's identity; each use re-resolves the host resource (`host_copy`, `shadow::find`) and copies only if it is the cached one; the entry holds a reference to the resource so its pointer cannot be reused by another while cached (no ABA), the cache is bounded and drops its least recently used entries, and it returns the same `Kept` and twin state as making would.
